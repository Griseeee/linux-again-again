# Отчёт по практической работе: Управление фоновыми процессами и обработка SIGHUP

## 1. Подготовка тестовой программы

В рабочей директории создан тестовый скрипт `alive.sh` с шебангом и бесконечным циклом:

```bash
cat << 'EOF' > alive.sh
#!/usr/bin/bash
while true; do
    echo "I am still alive"
    sleep 1
done
EOF

chmod +x alive.sh
```

---

## 2. Основная часть: Запуск и обработка SIGHUP

### 2.1 Команда запуска

Для запуска процесса в фоновом режиме с защитой от закрытия сессии терминала и перенаправлением вывода использована команда:

```bash
nohup ./alive.sh > stdout.log 2> stderr.log &
```

*Зафиксированный идентификатор процесса (PID):* **`11533`**

---

### 2.2 Теоретическое обоснование: Механизм сигналов при закрытии SSH-сессии

#### Какого рода сигнал приходит и почему?
При закрытии окна эмулятора терминала или завершении SSH-сессии происходят следующие события:
1. Демон `sshd` закрывает выделенный виртуальный терминал (псевдо-терминал `pty`/`pts`).
2. Командная оболочка (`bash`), являющаяся лидером сессии (Session Leader), получает уведомление об обрыве связи с управляющим терминалом.
3. Оболочка рассылает сигнал **`SIGHUP` (Signal 1 — Hangup)** всем дочерним процессам и заданиям (jobs), зарегистрированным в её таблице заданий.

#### Что происходит с обычным процессом?
По умолчанию стандартная реакция процесса на сигнал `SIGHUP` — немедленное завершение работы (`Terminate`). Если запустить скрипт обычной командой `./alive.sh &`, то при выходе из SSH оболочка отправит ему `SIGHUP`, и процесс погибнет.

#### Почему `nohup` спасает процесс?
Утилита `nohup` (No Hangup) при запуске команды подменяет обработчик сигнала `SIGHUP` для создаваемого процесса на `SIG_IGN` (Игнорировать). В результате, когда `bash` при закрытии сессии посылает `SIGHUP`, процесс `11533` игнорирует его, отвязывается от терминала и продолжает выполнение под управлением родительского процесса `init`/`systemd`.

---

### 2.3 Подтверждение жизнеспособности процесса после повторного входа

После выхода из SSH-сессии (`exit`) и повторного подключения по порту `2222`:

```bash
ssh -p 2222 root@127.0.0.1
ps aux | grep alive.sh
```

**Точный зафиксированный вывод команды `ps aux`:**

```text
root       11533  0.0  0.0   5272  3552 ?        S    18:47   0:00 /usr/bin/bash ./alive.sh
root       11823  0.0  0.0   4300  2276 pts/2    S+   18:51   0:00 grep alive.sh
```

**Анализ вывода:**
* **PID:** `11533` (процесс сохранил тот же ID, что и до закрытия SSH).
* **STAT:** `S` (Interruptible Sleep — процесс активен и ожидает задержки `sleep 1`).
* **TTY:** **`?`** (Символ вопроса в колонке TTY подтверждает, что процесс успешно отвязался от закрытого управляющего терминала `pts/1` и перешёл в фоновый/демонический режим).

## 3. Задание со звёздочкой (*): Работа с потоками вывода

### 3.1 Разделение потоков `стдаут` и `стдерр`
При запуске программы потоки вывода были перенаправлены в отдельные файлы с помощью файловых дескрипторов:
* `стдаут` (ФД 1) → `stdout.log`
* `стдерр` (ФД 2) → `stderr.log`

```баш
nohup ./alive.sh > stdout.log 2> stderr.log &
```

---

### 3.2 Чтение вывода у работающего процесса "на лету"

Прочитать вывод работающего процесса, не останавливая его и не мешая записи логов, выполнено двумя способами:

#### Способ 1. Чтение лог-файла
```баш
хвост -n 5 stdout.log
```
*Результат:*
```текст
Я все еще жив
Я все еще жив
Я все еще жив
Я все еще жив
Я все еще жив
```

#### Способ 2. Чтение напрямую через файловые дескрипторы ядра (`/процесс`)
Поскольку в Linux файловые дескрипторы открытого процесса представлены в виртуальной файловой системе `/процесс/$PID/fd/`, обращение к ним позволяет читать вывод процесса напрямую из памяти/потока:

```баш
cat/proc/$(pgrep -f alive.sh)/fd/1
```

*Зафиксированный вывод терминала:*
```текст
Я все еще жив
Я все еще жив
Я все еще жив
Я все еще жив
...
```

## 4. Итоговая сводка для сдачи

| Требование | Решение / Доказательство |
| :--- | :--- |
| **Команда запуска** | `nohup ./alive.sh > stdout.log 2> stderr.log &` |
| **Сигнал при закрытии** | `ВЗДОХНУТЬ` (Сигнал 1). `нохуп` перехватывает сигнал и устанавливает флаг `SIG_IGN`. |
| **Доказательство выживания** | Вывод `пс аукс` после повторого SSH-вода с PID `11533` и ТТИ `?`. |
| **Чтение stdout/stderr** | Команды `хвост -f stdout.log` или `кот/proc/11533/fd/1` без остановки процесса. |
